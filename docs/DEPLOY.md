# 部署說明（GitHub Pages）

本專案是純靜態網站，沒有建置步驟，可以直接用 GitHub Pages 部署。以下的 `<帳號>` 請換成實際的 GitHub 帳號名稱。

## 一、事前確認

- **儲存庫可見度**：免費帳號只能在**公開**儲存庫使用 GitHub Pages；私人儲存庫需要付費方案（GitHub Pro 以上）。
- **公開後的內容**：儲存庫設為公開後，所有檔案與完整的 commit 歷史（包含 commit 訊息）都會公開。
- **分支**：網站內容在 `main` 分支的根目錄，`index.html` 就在最上層，不需要另外設定資料夾。

## 二、開啟 GitHub Pages

1. 進入儲存庫頁面，點上方的 **Settings**。
2. 左側選單點 **Pages**。
3. 在 **Build and deployment** 區塊：
   - **Source** 選 **Deploy from a branch**
   - **Branch** 選 **`main`**，資料夾選 **`/ (root)`**
4. 按 **Save**。

## 三、確認部署成功

1. 到儲存庫上方的 **Actions** 分頁，會看到名為 **pages build and deployment** 的工作。
2. 等它變成綠色勾勾（通常 1 到 3 分鐘）。
3. 回到 **Settings → Pages**，頁面上方會顯示網站網址，格式為：

   ```
   https://<帳號>.github.io/<儲存庫名稱>/
   ```

4. 開啟網址，確認能看到主選單並開始遊戲。

## 四、更新網站

推送新的 commit 到 `main` 分支後，GitHub Pages 會自動重新部署，不需要其他操作。部署進度一樣在 **Actions** 分頁查看。

## 五、常見問題

### 開啟網址出現 404

- 剛開啟 Pages 時需要等部署完成，先到 **Actions** 分頁確認工作已經是綠色勾勾。
- 確認 **Settings → Pages** 的分支是 `main`、資料夾是 `/ (root)`。
- 確認網址結尾有儲存庫名稱，例如 `https://<帳號>.github.io/<儲存庫名稱>/`。

### 推送了新版本，網頁卻沒有更新

- 先確認 **Actions** 分頁的部署已經完成。
- 瀏覽器可能還在使用舊的快取，請強制重新整理：
  - Windows／Linux：`Ctrl + Shift + R`
  - macOS：`Cmd + Shift + R`
  - 手機：關閉分頁後重新開啟，或清除該網站的瀏覽資料

### 字型、圖示或程式載入失敗

- GitHub Pages 的網址**區分大小寫**，本機測試時（特別是 Windows 與 macOS）不會發現這個問題。檔名與程式碼裡引用的路徑大小寫必須完全一致。
- 所有路徑都必須是相對路徑（例如 `js/main.js`，而不是 `/js/main.js`），因為網站位在 `/<儲存庫名稱>/` 子路徑底下。本專案目前全部使用相對路徑。
- 按 `F12` 開啟開發者工具，在 **Console** 與 **Network** 分頁可以看到是哪個檔案載入失敗。

### 切換主題後，Safari 的分頁圖示沒有改變

Safari 對動態更換 favicon 的支援有限，重新整理頁面後就會顯示目前主題的圖示。這不影響遊戲功能。

### 最高分和設定不見了

最高分與設定存在瀏覽器的 `localStorage`，依網址分開存放。部署後的網站和本機測試（`localhost`）是不同網址，資料不會共用；使用無痕模式時，關閉視窗後資料也會清除。

## 六、部署後的實機測試

開發期間以 Chromium 自動化測試與手機模擬驗證，以下項目需要在部署後用實體裝置確認：

- [ ] **iPhone Safari**：版面完整顯示、滑動操作正常、不會誤觸頁面捲動或縮放
- [ ] **Android Chrome**：同上
- [ ] **Mac Safari**：鍵盤操作、七個主題的畫面、像素字型顯示
- [ ] **橫向手機**：遊戲區域完整顯示，主選單可以捲動到「開始遊戲」按鈕
- [ ] **語言**：手機系統語言為中文與英文時，分別預設顯示對應語言
